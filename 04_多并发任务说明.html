自选分镜版本与一键出片

“03 批量制作”的每个镜头都有“选择分镜版本”，可看图比较并选用；不调用模型。已选版本优先于最新候选，不会因重做图片而自动替换。一键确认窗口也可逐镜换版本、使用自定义图或选择重新生成，并实时计算图片和视频请求数。视频的手动选择与自动采用均可使用；缺片窗口增加“自己选择视频版本”，批量采用只是快捷选项。

01 / QUEUE BOUNDARIES

本地合成队列与真实 API 队列分别运行

原有前端负责模板合成、画布和静帧运镜；新增后端负责真实云端请求及媒体缓存，api.js 将真实任务与浏览器项目关联。两者的任务 ID、状态、并发和保存位置不同，前端演示任务的进度不能充当供应商推理进度。core.tick() 跳过 remote 任务，API 状态由 api.js 约每 1.8 秒读取后端同步；API 任务不使用本地模拟百分比。

前端原有合成队列

core.js 的 state.tasks、tick()、complete() 驱动定时进度与浏览器合成。轻任务可设 1 / 2 并发，视频类任务独占。

浏览器使用独立 IndexedDB 库 forma-api-studio-v2；本地“video”结果仍是关键帧占位，最终静帧运镜视频在导出时编码。

后端真实 API 队列

server.py 的 JOBS、scheduler()、worker() 发起百炼请求，异步视频保存远端 task ID 后持续查询。

任务保存在本机 .runtime/jobs.json，媒体缓存在 .runtime/files/；并发受配置和任务类型限制。

“云端已完成”“本机已缓存”“已应用到项目”是三个不同事件。后端完成返回结果引用，并不直接修改前端项目。应用结果还需检查项目、对象和编辑版本，防止较晚完成的结果覆盖用户新修改。

本说明以已读代码为基准；首次联调批次有 4 次真实模型 POST，去重为 4 个任务、5 条终结事件；分镜本地重新校验与一次真实 MP4 编排导出也有记录。但供应商限流、取消计费、重启及网络异常恢复尚未据此验证。产品验收和模型评测分别见 02 · 交互说明与03 · 模型评测报告。

02 / API SCHEDULING

总并发与模型类型双重限额

规则代码实际行为产品含义
总量限制配置值限制在 1–2；BUSY 记录已分配 worker 的任务，最多达到该配置。这是本应用同时占用的执行槽位，不是供应商保证的实际 GPU 并行数。
类型限制每次最多一个 image worker、一个 video worker；文本任务共用总槽位，不单设文本类型上限。总量为 2 时图像与视频可以并行；两个文本也可能占满槽位。
槽位生命周期从启动 worker 到 finally 释放，包含 API 等待、视频查询、媒体下载和结果记录。视频远端排队期间也占用一个本地执行槽位，不会无限放开视频提交。
选择顺序约每 400ms 扫描按字典顺序保存的任务；选择 queued / waiting_remote，跳过忙碌或依赖未完成的任务。不是严格所有任务统一 FIFO：当前不可执行项会被跳过，让后续满足条件的任务启动。
手工重排仅 queued 任务可上移，交换到前一个 queued 任务之前，顺序一并持久化。不抢占已发出的请求；当前没有等待时长上限、同模型合并或自动公平调度。
依赖提交时要求前置 ID 已存在；运行前仅当前置 status=done 才启动。视频可从前置结果的第一个媒体文件取首帧。前置失败、未知或取消时，下游继续等待；不会自动取消或级联重试。调用方需提供正确的图像依赖。

无可用 Key 时调度器不启动新任务；worker 执行前检查可用缓存空间。图像 / 视频并行的依据是云端配额、请求状态和预算，不使用本机显存作为判断理由。配置变化对新 worker 生效，不表示已提交的远端请求可以即时停止。

03 / STATE MACHINE

状态要表达确定性，不能掩盖未知

queued ──依赖满足、取得槽位──▶ running ──worker 准备请求──▶ submitting
                                                               │
                          文本 / 图像响应 + 本地处理完成 ──────┤──▶ done
                                                               │
                          视频取得 remote_id ────────────────┘──▶ waiting_remote
                                                                       │
                                  查询既有远端任务 + 下载完成 ───────────▶ done

POST 响应不确定 ──▶ unknown        确定错误 / 下载失败 ──▶ failed
有 remote_id，查询暂停 ──▶ interrupted ──resume──▶ waiting_remote
取消请求 ──▶ canceled（远端仍可能执行；返回结果可被缓存）
failed / unknown / interrupted / canceled ──符合条件且确认费用──▶ queued
                                           （retry：attempt + 1）

这是后端内部状态机。running 主要是调度器已分配 worker 的短暂状态；waiting_remote 可包含供应商排队、处理中、查询错误等待和下载阶段。stage 提供更具体说明，不能由本地时间线伪造远端百分比。

状态何时出现允许的下一步
unknownPOST 超时、连接异常、不可解析响应、部分 5xx，或视频创建未取得远端 ID；也可由重启时未确认的请求产生。先核对供应商记录；没有自动重发。用户明确确认费用后才能通过 retry 再次请求。
failed确定 API 错误、schema 校验失败、本地媒体处理失败等；不等于一定未计费。文本已保留原响应时优先检查是否可本地 revalidate；确需重新请求才确认费用后 retry。有远端 ID 且未确认远端失败时应 resume 查询。
interrupted已有远端 ID，但查询暂停、Key 缺失或 Host 不匹配等导致无法继续。恢复相应配置后 resume；不重新创建远端任务。
canceled应用收到取消动作；若请求已经开始，worker 可能仍在执行。等待结果或保留缓存；恢复远端查询会清除取消意图，调用前需理解可能继续获得结果。
04 / DATA CONTRACT

输入快照和远端 ID 跨重启保留

位置 / 字段用途当前边界
jobs.json保存任务输入、状态、顺序、模型、Host、依赖、结果和重试历史。写临时 JSON、flush / fsync 后替换正式文件；使用进程内 RLock。不是多进程数据库，不支持多个服务进程共享写入。
id / fingerprint本地业务请求 ID；完整提交对象的 SHA-256 指纹用于比较相同 ID 的输入。相同 ID + 相同输入应返回已有任务；输入不同返回冲突。它不是供应商提供的幂等键。
request / image_files保存请求参数；输入图片按内容 SHA-256 命名存到 inputs，任务引用文件名。公开任务响应移除 request、fingerprint 和 provider_urls；原输入及临时供应商 URL 仍保留在本机任务库。没有自动清理策略。
model / host冻结提交时的模型与地域 Host。Key 仅保留于环境配置或进程内，不写入 job；重启后使用当前配置，Host 不匹配时阻止恢复执行。
remote_id / provider_request_id异步远端任务 ID 与供应商回执标识，用于继续查询和排查。文本 / 同步图像通常只有请求回执，不具有可查询的异步 remote_id。
attempt / history初始 attempt 为 0；用户确认 retry 后递增，历史保留上次部分状态、usage 和结果。同一任务中的整数计数，不是每次操作的独立事件 ID；本地 revalidate 不增加 attempt，会添加 local_revalidation 历史。history 仍不是完整事件日志。
cancel_requested / result记录取消意图，区分取消后返回的结果与正常完成。结果可留在 canceled 任务中，并通过任务列表“查看结果”预览下载；是否应用到项目不由后端自动完成。
metadata / revision项目 ID、对象 ID、SKU、镜头、版本等关联信息。后端只做白名单存储；api.js 用项目 ID 关联素材，文本方案应用时检查 revision，冲突时提示确认。

任务库无法解析时服务拒绝创建新库，以保护原文件。持久化有助于重启恢复，但不等于任意断电都不会损坏磁盘数据；输入文件、媒体文件和 job 完成状态也不是一个跨文件数据库事务。

05 / UNKNOWN SUBMISSION

结果未知时先对账，再决定重提

  1. 应用向后端重复提交。应复用相同本地请求 ID 和相同输入，后端返回已有记录，避免把一次点击变成多个业务任务。
  2. 后端向供应商 POST 后未拿到确定响应。转为 unknown；不能从超时推出供应商没有受理，也不能自动切换模型再次提交。
  3. 已有 remote_id。恢复只 GET 查询既有任务。retry 在远端状态未确认为 FAILED / CANCELED 时拒绝，并提示使用 resume。
  4. 确需重新生成。retry 要求明确的 confirm_cost，并递增 attempt；有远端任务但只是想得到新版本时，新建业务任务，保留原回执。

幂等有两层边界。本地 ID 去重无法解决“供应商已经接收，但回执尚未持久化就崩溃”的窗口。同步文本 / 图像没有本实现可继续查询的远端 ID；这类情况需要查供应商记录，避免重复付费。

POST 提交前将状态持久化为 submitting，视频收到 task ID 后再次持久化，再进入查询。这个顺序有助于识别不确定窗口，但不提供跨供应商原子提交。当前实现已在最终写锁内再次核对 ID 与指纹，避免两个请求在首次检查后相互覆盖；仍需通过并发相同 ID 的回归测试验证。

LOCAL RECOVERY / NO NEW INFERENCE

重新校验原响应，与重新调用模型分开

文本任务为 failed、已保存 raw_text 且不在 BUSY 时，界面提供“重新校验原响应”；服务端也检查这些前置条件，canceled 任务不能借此改为 done。后端 revalidate 从保存的 JSON 文本重新解析，再调用当前 validate_result；不执行 api_call、不增加 provider_post_count，也不增加 attempt。通过后写回 result / done，保存 revalidated_at、追加 local_revalidation 历史，并记录新的终结事件。

本次分镜响应含 6 镜头、2 集，其中 3 个镜头无字幕。旧规则误把空字符串视为无效，修复后允许 subtitle 为空，但仍要求其为字符串，title / prompt 保持非空、角色 ID 必须来自输入。重新校验原响应后通过；这证明此次本地恢复路径可用，不能称作模型自动重试或第二次调用成功。

原始首次错误和旧 finished 时间保留。修复完成另记 revalidated_at，因此旧 elapsed_ms 不包含人工作业和修复等待。重新校验不会重新核验图片或视频；素材下载恢复仍遵循对应机制。

06 / CANCEL & APPLY

取消后停止应用，不承诺远端立刻停止计费

取消时机当前后端行为应向用户说明
尚未启动设置 cancel_requested 与 canceled；调度器不再选择该任务。若 worker 尚未发请求，早期检查可直接返回。该任务不继续启动；原输入和已有结果保留。
同步请求已发出不会中止正在阻塞的 HTTP 请求；若文本 / 图片结果返回，仍执行本地处理和缓存，最终状态为 canceled。远端请求可能已经产生费用；不能把本地取消描述为供应商取消成功。
视频已取得 ID不调用供应商取消接口；运行中的轮询与下载不会因本地取消立即退出，结果若返回会缓存到 canceled 任务。远端可能继续生成并计费；缓存结果留供核对，应用层不应自动替换画布。
取消后关闭服务进程内查询和下载停止；重启时 canceled 任务不自动恢复查询。不能保证关闭后仍完成缓存；如需继续取回，使用原 remote_id 恢复查询，并留意结果链接时效。

原前端合成队列有自己的取消规则：complete() 在异步合成前后检查任务是否仍为 completing，被取消的任务不会再追加新结果。这个行为只适用于浏览器合成队列，不能用来证明供应商的推理已停止。

结果应用验收：api.js 仅自动导入 status=done 的结果，按项目 ID 找到当前或归档项目，按 job.id + attempt 去重。图片先加入素材区，不自动替换当前画布；文本方案先预览，由用户应用，revision 不同会提示确认。镜头图片只在明确点击“应用到镜头画面”时替换，并检查原镜头仍存在；当前未对该手工替换单独提示 revision 冲突。已取消但具有 result 的任务也可主动查看，仍不自动应用。recovered=true 的任务缺少完整输入快照，因此不自动导入项目。

07 / RESTART & RESUME

重启恢复查询，不恢复扩散计算

重启时记录启动恢复逻辑限制
submitting / running，无 remote_id改为 unknown，提示上次请求结果不明。不自动再 POST；可能已被供应商接收，需核对。
有 remote_id，且非 done / failed / canceled转 waiting_remote，重新查询同一远端 ID。要有对应 Key 与 Host；不保证远端任务仍在有效期。
queued保留在队列，配置可用且依赖满足后可执行。重启不会丢掉输入；当前 Key 为空时不会启动。
done / failed / canceled保留原状态，不自动执行。失败且有 ID 的任务可手工 resume；文本有 raw_text 时可重新校验原响应；已完成任务不会在启动时重新验证缓存文件完整性。

真实视频的分集编排

API 模式下，app.movie() 调用 api.js 的 recordClips()：按镜头 ID 找到最新 api-video，逐个加载本机 MP4，解码并绘制到画布，叠加当前字幕，再通过 MediaRecorder 录制输出。输出宽度 960、画布帧率 24；使用当前浏览器支持的 WebM / MP4 编码，无音轨，属于本地重新编码，并非无损拼接。

单镜头采用编辑时长与原视频时长的较小值；未实现补帧、插帧或自动延长。缺少真实片段、缓存不可读、解码或编码不支持时明确报错，原始 MP4 保留供单独下载；不会自动改用静帧素材。本次浏览器已完成一次真实 MP4 加字幕编排导出：WebM VP9、333,277 字节、960 × 540，实际解码通过。原 MP4 是 960 × 960、2 秒。该样本只验证一次导出路径，不证明多镜头、多集或长片稳定性。

下载失败与恢复并未全部覆盖

视频保留 remote_id，手工 resume 可以重新查询结果并重新下载；下载从头开始，没有 HTTP Range 断点续传。图像是同步接口，已保存 provider_urls 但当前没有“只重下图片”的专用动作；直接 retry 会重新请求图像生成，可能再次计费。不要将其描述为无成本恢复。

每轮视频查询最长约 30 分钟，常规查询间隔约 4 秒；查询错误时退避到最长约 15 秒，暂停后保存远端 ID。服务端返回 UNKNOWN 时，当前实现继续查询直到暂停；未实现自动过期识别或供应商账单对账。此处为代码行为，不代表已验证供应商可承受该查询频率。

08 / CACHE & LOGGING

媒体本地保存，临时 URL 不等于永久素材

对象实际保存与限制不应作出的承诺
输入参考图存到 .runtime/inputs；每张 Base64 解码后不超过 10MB；按内容哈希复用同一输入文件。后端这一步不真正解码图片验证尺寸、透明通道或格式内容，需在前端规范化并另作文件验证。
生成媒体仅下载允许的供应商资源域名；图像上限 25MB、视频上限 150MB；先写 .download 临时文件，完成后替换正式文件。目前检查 MIME、大小和最小字节数，没有真正解码媒体、SHA 校验或断点续传；“下载成功”不能直接等同内容可播放。
本地媒体服务通过 /api/files/ 提供缓存文件，支持单段 bytes Range；HTTP 头为 private,max-age=3600。3600 秒是客户端缓存有效期，文件不会因此自动删除；本机目录没有自动 TTL 清理。
远端链接与任务provider_urls 与 remote_id 保存在任务库；供应商结果链接 / 任务查询存在有效期，应尽快下载。本后端没有自动刷新失效签名或修复过期 URL。有效期届满不能保证还可恢复。
Key 与日志Key 在 .env / 进程配置与内存 JOB_KEYS；公开配置只返回 configured 等状态。HTTP 常规访问日志关闭，evaluation 不记录请求体或 Key。jobs.json 仍保存输入、raw_text 和带签名媒体 URL，不是可随意公开的审计文件；不要把任务库当完全脱敏日志。

evaluations.jsonl 记录任务结束事件，包含模型、状态、时间、usage、远端 ID 和错误码。当前 elapsed_ms 从首次 started 到本次结束，不包含本地排队但可能包含停机及恢复等待；queue_ms 与 submitted_to_finished_ms 分别记录调度前间隔及创建到结束的累计时长。provider_post_count 在调用 POST 前递增，属于发起尝试计数，不等于供应商受理或计费次数；查询恢复不新增此计数。/api/evaluations 以 terminal_event_count 命名行数，不再把终结事件冒充调用数。schema_valid 仍只由文本任务最终 done 推出，不是独立评分器。当前日志有 5 条终结事件，按业务 ID 去重为 4 个任务，累计 4 次模型 POST；前端导出提示也分别显示终态事件数与模型 POST 数。分镜第一次本地校验失败，revalidate 后追加 done 事件但 provider_post_count 仍为 1；不得把事件行数或每行累计计数直接相加当调用数。没有据此验证并发、取消、重启或下载恢复；具体样本见 03 报告。

09 / EVENT SCENARIOS

让每个异常都有可解释的下一步

事件任务与成果界面应呈现的操作
一张电商图 + 一个视频总并发 2 且满足类型限制时可并行；图像先完成后可继续编辑。分别显示任务阶段；不显示编造的供应商进度百分比。
分镜图失败依赖该图的视频不启动；其他无依赖任务可继续。定位前置错误，修复 / 重试前置，或取消下游；不自动重做整集。
浏览器刷新后端进程仍在时 API 队列继续；原前端合成队列则把运行状态恢复为中断。重新拉取后端 jobs；不要因浏览器旧状态重建同一远端任务。
服务重启依据持久化状态区分 queued、unknown 和已有远端 ID。能查的继续查，不确定的提示核对；保留已缓存结果。若浏览器缺少原任务，poll() 会从后端元数据重建 recovered=true 的前端条目；可预览下载结果，但不自动导入缺少完整输入快照的项目。
取消后供应商成功若 worker 未结束则缓存结果并保持 canceled；下游因父任务未 done 不自动启动。显示“取消后返回，未应用”；手工取用应是明确操作，不自动改画布。
创建 POST 超时unknown，无自动重发；不能确定是否计费。展示原业务 ID 和错误；核查后若重提，明确提示新增费用风险。
成功后媒体下载失败任务可能 failed，但供应商已成功；费用不能按本地失败归零。视频优先查询原 ID；同步图像当前只重下能力不足，需要单独处理。
改了项目后旧任务完成结果属于提交时输入快照，不应覆盖当前版本。新结果进入素材区，显示版本差异；由用户决定是否应用。
10 / VERIFICATION STATUS

静态实现已核查，真实异常路径待测

待实测 本文没有把代码阅读或本地模拟测试当作供应商验证。以下清单需要记录输入、时间、任务 ID、供应商回执、结果文件和状态，分别统计。

  • 并发提交两张图片、两个视频与文本，确认总量及类型限制，无超发；并检查图像与视频可同时执行。
  • 以完全相同 ID 和输入并发 POST 两次，确认仅一个业务任务及一次远端创建；再用同 ID 不同输入检查 409 冲突。
  • 在图像前置任务失败、重试、取消三种情况下观察视频依赖，确认未越过前置条件。
  • 在排队、HTTP 已发出、取得远端 ID、下载中、已完成几个阶段取消，检查结果保留和应用行为。
  • 模拟 POST 超时 / 连接断开，确认 unknown 不自动重发；模拟 GET 网络错误，确认保留原 ID 查询。
  • 分别在没有远端 ID和已有 ID 时终止服务，再启动；核查未知状态、恢复 ID、重复请求及账单。
  • 模拟文件过大、下载失败、缓存文件丢失和磁盘不足，确认错误准确；不要以生成失败掩盖下载失败。
  • 项目编辑后应用旧结果，确认版本保护；导出备份后检查浏览器项目与后端任务库是否都可恢复。
