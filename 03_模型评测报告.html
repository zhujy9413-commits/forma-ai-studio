续拍依赖网页读取尾帧与提交后镜，需保持页面打开。已提交任务由后端持久化；恢复页面后仅在已授权批次内续接尚未提交的计划，已登记任务ID不重复创建。尾帧读取或提交异常时暂停，不自动付费重试。原片段与版本均保留。续拍提示以实际首帧服饰与姿态为准；这不保证人物动作、物理反射或跨镜故事质量，也不是首尾帧模型模式或插帧功能。

自选分镜版本与一键出片

“03 批量制作”的每个镜头都有“选择分镜版本”，可看图比较并选用；不调用模型。已选版本优先于最新候选，不会因重做图片而自动替换。一键确认窗口也可逐镜换版本、使用自定义图或选择重新生成，并实时计算图片和视频请求数。视频的手动选择与自动采用均可使用；缺片窗口增加“自己选择视频版本”，批量采用只是快捷选项。

当前短剧提供两条路径。在“03 批量制作”点击“一键出片”，确认各镜头使用的分镜版本及调用数量后，复用已选图片、仅补生成缺失图片，并制作视频。默认自动采用并合成当前集预览，也可选择“保留为候选，我自己选择视频版本”。全部剧集的片段均保留，可逐集预览或批量导出。需要控制画面时，使用“仅制作分镜图 → 检查 / 确认分镜 → 用确认分镜生成视频 → 视频版本采用”的逐步路径。单镜头返修仍不自动覆盖已选版本。

一键结果标记为自动初稿，未经过人工质量审核。该入口不会自动重新拆分故事或替换当前分镜表。复用已有分镜时直接固化该图作为视频输入，不创建图片任务；新增分镜与视频按后端 depends_on 关联，视频使用本批次图片结果；已提交任务在后端持久保存。恢复页面只查询，不自动补发或重提模型请求。生成期间的编辑冲突会保留结果、阻止自动覆盖；失败、未知提交、取消时下游等待并显示异常，需要用户核查。

合成使用浏览器本地编码，需保持页面打开并位于前台。预览失败保留原片段，不自动重复编码；用户可再次点击预览。全部提交前关闭页面会留下未完整提交状态，必须到任务中心核查。停止本批次会停止本地后续及自动采用，不保证撤回供应商运算或费用。

导出前如果缺片，现在显示具体镜头与匹配情况。已有匹配视频时可批量采用并预览，不调用模型；没有匹配视频时不会将分镜图冒充真实视频，提供制作入口和无调用的已验证案例入口。

三个容易使评测失真的边界

  1. 合法 JSON 不等于业务正确。文本基线先使用非流式、关闭思考和 JSON Object 输出；提示词明确要求 JSON，服务端返回后再校验字段、类型、镜头编号和角色引用。HTTP 直调的 enable_thinking 在顶层；Python OpenAI SDK 才通过 extra_body 传扩展参数。结构化输出说明、参数说明。
  2. 参考图输入先规范化。图像编辑需 1–4 张参考图，支持 Base64 Data URL；默认输出数并非测试期望，必须显式 n=1。官方输入不支持 PNG 透明通道，应先按选定背景扁平化，保存原文件及规范化文件的 hash，按尺寸和文件大小限制校验。图像输入与数量限制。
  3. 创建成功不等于视频交付成功。基线采用 first_frame，不与 reference_image 等参考模式混用；明确设置是否输出音轨。保留远程 task ID，成功后下载视频并验证可解码，再计入交付成功。视频任务及结果链接有时效，应及时转存。视频模式与异步结果。

seed、prompt_extend、参数和参考图均需固定，但不能把相同 seed 当作输出逐像素可复现的保证。官方示例耗时和能力描述均不是本项目实测值。

角色 ID 有效率检查每个镜头引用均来自本次输入角色表，且必需引用非空；同时报告无错误镜头占比与整份输出全通过比例。角色引用不得凭空增加；发现错误禁止该镜头进入视频任务。
可核对事实保留对用户明确给出的颜色、数量、名称、尺寸、角色设定逐项检查；事实缺失、冲突和无依据新增分别计数。文本规则能核对的事实自动算，其余人工标注。关键商品属性或角色身份错误判不可用；不要将视觉属性全称为自动客观验证。
文件规格正确率实际解码检查图片像素、格式与数量；视频检查编码、分辨率、时长、帧率和音轨，与请求参数及预期对照。验收集规格对应率目标 100%；内容质量另算。
延迟分解以单调时钟记录提交到本地结果落盘的 E2E；应用等待、HTTP 耗时、远程排队、执行、轮询发现及下载分别记录。若服务未返回某阶段时间，写不可观测。同条件下报告中位数、范围与样本量。小样本不报可靠 p95；不把轮询间隔当模型生成时间。
实际可用产出经人工质量放行的图片 / 镜头数量；首次可用率、达到可用结果的重试次数；每份可用输出的总时延和总费用。同时看质量与成本，避免把低质大量输出算作高产能。
恢复与去重模拟客户端断连、重启和查询超时；检查已有 remote task ID 是否继续查询、是否重复提交、完成文件和输入版本是否保留。固定异常集重复创建计数为 0；涉及外部调用的未知结果先核对，不自动重发。

角色或商品的特征相似度、轮廓重叠等可以作辅助报警信号，但受姿态、光照和背景影响；不替代人工商品保真或角色一致性判定。所有未执行目标均不得出现在“已达到”栏。

06 / HUMAN REVIEW

主观评分也要有可复用锚点

至少由 3 名评审独立评分，隐藏方案名称并随机展示顺序。商品评审对照原图与属性清单；短剧先连续播放，再检查跨镜头角色。保留每位评审分数、中位数和分歧，不只展示平均分。评分差距达到 2 分时复核原因。

维度1 分3 分5 分
脚本叙事与分镜核心事件错误、因果断裂，镜头无法执行。基本可理解，但节奏、对白或镜头需明显修改。意图清楚、镜头可执行、转场连贯，可直接进入制作。
商品保真商品类别、形状、颜色、标识或数量发生关键错误。主体大体相似，有明显材质、边缘或局部细节需修复。关键属性保持，新增场景与商品关系自然。
构图与商业可用性主体被遮挡、版式或文字影响使用。可继续修改，但仍需较多排版或修图。主体突出、信息清楚，符合目标投放位置。
角色一致性身份或服饰明显变化，难以认作同一角色。可辨认但细节漂移明显，跨镜头需修复。跨姿态与换景仍能稳定识别，外观连贯。
时序与动作严重变形、闪烁或动作逻辑错误，无法使用。主体动作可理解，局部不自然或明显跳变。动作与运镜自然，跨帧稳定，无明显违和。

2 分和 4 分分别位于相邻锚点之间；4 分表示可用但需轻微修改。初始放行规则为相关维度中位数均 ≥4，且没有关键商品属性、角色身份或剧情事实错误。该规则是产品质量门槛，不是当前模型已取得的成绩。

07 / QUALITY–LATENCY DECISION

成品质量优先，等待和成本可解释

质量和速度只能保一个时，成品选择质量。商品被画错或角色换脸，即使生成更快也无法交付。预览、批量排队和局部重做负责缩短用户感知等待；最终结果仍需通过质量门槛。

预览可使用较低分辨率，但需标明预览，并说明成品重生成不保证完全相同。逐步制作在人工确认角色参考帧后创建视频；一键出片自动使用本批次已完成分镜图；结果不达标时保留原输入和已完成成果，重做单项。不能用清晰度或模型品牌代替商品保真与叙事检查。

本版 API 调度计划为总并发最多 2、图像最多 1、视频最多 1，可在账户限额允许时让图像与视频并行。限制依据供应商配额、限流、预算与请求状态，不再按本机 GPU 显存解释。真实提交超时但结果未知时进入待核对状态；已有远程 ID 时重启后只查询原任务，不通过重发追求表面成功率。

具体页面状态和异常操作见 02 · 交互说明；调度与恢复规则见 04 · 多并发任务说明。
